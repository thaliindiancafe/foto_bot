# Foto Bot

Telegram-бот на Node.js + TypeScript + Telegraf.

## 📋 Требования

- Node.js >= 18.0.0
- npm или yarn

## 🔧 Установка

```bash
# Установка зависимостей
npm install

# Настройка окружения
cp .env.example .env
# Отредактируй .env и добавь BOT_TOKEN
```

## ⚙️ Настройка

Заполни `.env`:

```env
BOT_TOKEN=your_bot_token_here
DATABASE_URL="file:./dev.db"
```

Токен получить у [@BotFather](https://t.me/BotFather).

## Google Cloud (Sheets + Drive)

### Service Account JSON (`GOOGLE_SERVICE_ACCOUNT_JSON`)

1. [Google Cloud Console](https://console.cloud.google.com/) → выбери проект (например `smenapro-496214`).
2. **APIs & Services → Library** — включи **Google Sheets API** и **Google Drive API**.
3. **IAM & Admin → Service Accounts** → свой аккаунт (например `smenapro-bot`) → **Keys → Add key → JSON** — скачается файл.
4. Открой файл в редакторе, скопируй **весь** JSON в одну строку в `.env`:

```env
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}
```

5. В Google **Таблице**: **Настроить доступ** → добавь email из поля `client_email` в JSON (например `smenapro-bot@smenapro-496214.iam.gserviceaccount.com`) с правом **Редактор**.
6. Папку на **Диске** с эталонами при необходимости расшарь на тот же email.

Я не вижу твой локальный файл в `Downloads` — это секрет; вставляй его только в свой `.env` на машине или в секреты сервера.

### OAuth: Client ID, Client secret, Refresh token (только для загрузки на Drive)

Нужны, если `ENABLE_GOOGLE_DRIVE=true` в `.env`.

1. **APIs & Services → OAuth consent screen** — заполни тип приложения, тестовых пользователей (если External).
2. **APIs & Services → Credentials → Create credentials → OAuth client ID** — тип **Web application** (не Desktop — у Desktop нет поля redirect URI).
3. Скопируй **Client ID** и **Client secret** в `.env`:

```env
GOOGLE_CLIENT_ID=....apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=...
```

4. В том же **Web** OAuth-клиенте → **Authorized redirect URIs → Add URI** — добавь **все три** (если порт 54321 занят, скрипт возьмёт запасной):

```text
http://127.0.0.1:54321/oauth2callback
http://127.0.0.1:38475/oauth2callback
http://127.0.0.1:41799/oauth2callback
```

5. В корне проекта в `.env` уже должны быть `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`. Запусти:

```bash
npm run google:oauth
```

Открой ссылку из терминала в браузере, войди под Google-аккаунтом, у которого есть доступ к папке на Диске. После успеха в терминале появится строка `GOOGLE_REFRESH_TOKEN=...` — добавь её в `.env`.

Если **refresh token не выдался**: [Google Account → Security → Third-party access](https://myaccount.google.com/permissions) — отключи доступ к этому приложению и снова выполни `npm run google:oauth`.

Если ошибка **`EADDRINUSE`** на порту 54321: закрой старый терминал, где висел `npm run google:oauth`, или в **Диспетчере задач** заверши процесс **Node.js**. После правки скрипт сам пробует порты **38475** и **41799** — для них URI уже в списке выше.

## 📚 Команды бота

- `/start` — Приветствие, регистрация, выбор активного чек-листа.
- `/menu` — Открыть главное меню (для админов — админ-панель).
- `/reload` — Только для админов: перечитать `src/config/checklists.json`
  → синхронизировать с БД.
- `/status` — Только для админов: краткая диагностика (DB / Storage / AI /
  Make webhook / Outbox).

## ⏸ Кнопка «Вернуться к пункту позже» (только для менеджера)

С 2026-05-15 у роли **manager** под каждым вопросом чек-листа появляется
дополнительная кнопка **⏸ Вернуться позже**. Это нужно для частой реальной
ситуации: менеджер «зависает» на одном пункте (например, открытие смены), а
параллельно должен выполнять обязанности другой роли (официант, бариста).
Чтобы не блокироваться на одной задаче и не «срезать» её через `Пропустить`,
пункт можно временно отложить.

### Как это работает

1. Менеджер нажимает **⏸ Вернуться позже** → пункт скрывается из основного
   потока. Бот переходит к следующему обычному вопросу.
2. Отложить один пункт можно **только один раз за чек-лист**. После этого
   кнопка `⏸` под этим пунктом больше не появляется.
3. Когда обычные пункты закончились, бот **не закрывает чек-лист**, а
   показывает **меню отложенных** — столбец инлайн-кнопок с непройденными
   пунктами (в стиле меню выбора роли). Менеджер сам выбирает порядок
   прохождения.
4. Чек-лист считается завершённым **только когда все отложенные пункты
   пройдены или пропущены с комментарием**. Завершить с «висящими»
   отложенными нельзя.
5. Пока идёт **AI-проверка только что загруженного фото**, кнопка `⏸` под
   этим вопросом временно скрыта — чтобы не оторвать фото от результата.
   После «Да / Нет / Переснять» отложить можно (если лимит не исчерпан).

### Обязательный комментарий при «Пропустить»

Связанное изменение: при нажатии **⏭ Пропустить пункт** бот теперь
**требует реальный комментарий** — минимум 5 символов. Однократные `—`,
`-`, точки и пробелы больше не принимаются. Так в таблице остаётся
понятная причина для каждого пропуска.

### Что попадает в Google Sheets

В листах **«Ресторан»** и **«Кофепоинт»** появились три новые колонки.
Шапку нужно один раз добавить вручную:

| Колонка | Заголовок              | Что попадает                                                   |
|---------|------------------------|----------------------------------------------------------------|
| **O**   | Отложено раз           | `0`, если пункт не откладывали; `1`, если откладывали.         |
| **P**   | Первое откладывание    | Время первого `⏸`, формат `дд.мм.гггг чч:мм`. Пусто, если 0.   |
| **Q**   | Статус откладывания    | `Отложено → пройдено`, `Отложено → пропущено` или пусто.       |

Колонки A–N работают как раньше, добавление O/P/Q обратной совместимости
не ломает.

### Итог в Telegram после чек-листа

Сотруднику и в чат менеджеров приходит расширенный шорт-лист. К стандартным
строкам (счёт `%`, фото, замечания) добавляются:

- `⏸ Отложено → пройдено (N): 1. <название пункта>` — что удалось закрыть
  через меню отложенных.
- `⏭ Пропущено с комментарием (N): 1. <название> — <комментарий>` — что
  пропустили и почему.

Эти разделы появляются только если такие записи есть.

### Кому НЕ показывается

- Официантам, бариста, поварам, су-шефам, шефам, хелперам, клинерам —
  кнопка `⏸` не отображается. Это сознательное ограничение MVP: фича
  оптимизирована под сценарий, когда менеджер ведёт сразу несколько ролей.
  Расширение на другие роли — отдельным решением клиента.
